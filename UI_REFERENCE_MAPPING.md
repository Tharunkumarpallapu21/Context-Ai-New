# ContextRoute AI — UI Reference Mapping

Each row records the strongest visual pattern source and the original ContextRoute AI adaptation. Source pages were inspected; no third-party screenshot is presented as a bundled app asset.

1. Onboarding 1 — Material 3 app bars and cards — quiet hero, progress, single next action.
2. Onboarding 2 — Citymapper journey framing — context-first copy with a simple illustration panel.
3. Onboarding 3 — Google Maps search surfaces — destination and intent hierarchy.
4. Onboarding 4 — Material 3 buttons and accessibility — clear completion action and low cognitive load.
5. Welcome / Get Started — Uber welcome state architecture — frontend-only entry points with honest copy.
6. Login — Material 3 text fields — strong labels, large touch targets, no false success.
7. Registration — Material 3 form grouping — progressive form rhythm and explicit validation.
8. Forgot Password — Material 3 empty/error states — calm recovery state with integration boundary.
9. Home / Map — Google Maps and Citymapper map-first layout — original placeholder canvas with floating search.
10. Destination Search — Google Places UI Kit autocomplete pattern — local empty state instead of results.
11. Search Results — Google Places cards — result stack is presentational and integration-pending.
12. Travel Context — Material 3 chips and segmented choices — one choice per context with clear selection.
13. Traveler / Group — Material 3 lists and steppers — compact detail rows and accessible inputs.
14. Route Preferences — Citymapper mode-selection hierarchy — preferences before route calculation.
15. Route Alternatives — Citymapper route comparison — three empty alternative slots, no fake distances or ETAs.
16. Route Details — Google Maps place/details card hierarchy — route facts stay unavailable until connected.
17. Navigation — Waze map-adjacent alert hierarchy — live guidance explicitly unavailable.
18. Explore — Google Places discovery grouping — categories and search entry without invented venues.
19. Nearby Places — Google Places nearby card pattern — permission and integration state.
20. Tourism Details — Google Maps detail page pattern — structured detail shell with no fabricated place facts.
21. Saved Places / Routes — Material 3 lists — local-only storage distinction.
22. Hazard Reporting — Waze community-reporting affordance — local report form and validation.
23. Report Status — Material 3 progress/status surfaces — submitted locally / pending integration.
24. Emergency Assistance — Material 3 high-emphasis buttons — direct device-action boundary, no false notification.
25. Notifications — Material 3 lists and empty states — no fabricated alerts.
26. User Profile — Material 3 top app bar and list rows — local profile state only.
27. Settings / Help / About — Material 3 menus and list groups — theme choice, support copy, product boundary.

References: [1] https://m3.material.io/components/navigation-bar/guidelines, [2] https://m3.material.io/components/bottom-sheets/accessibility, [3] https://mapsplatform.google.com/demos/places-ui-kit/, [4] https://citymapper.com/?lang=en, [5] https://www.waze.com/waze-app, [6] https://www.uber.com/us/en/blog/new-rider-app-architecture/
